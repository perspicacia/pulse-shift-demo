# 롱노트 설계와 검증

## 지원 채보와 조작

ASTRAL VEIL **LEVEL 2·6키**에서만 243개 노트 중 8개를 롱노트로 바꿉니다. 기존 시작 시각·레인·전체 노트 수를 유지합니다. 4마디마다 나오는 패드의 시작에 1~2박(약 0.48~0.95초)의 홀드를 배치하며, 끝은 박자 그리드에 맞춥니다. 동일 레인의 다음 노트의 이른 판정 구간과도 겹치지 않게 여유를 둡니다. 다른 곡·4키·ASTRAL LEVEL 3 채보는 그대로입니다.

S·D·F / J·K·L 키 또는 레인 버튼을 머리가 판정선에 닿을 때 누르고, 끝이 도착할 때까지 유지합니다. 원근 몸통은 레인과 같은 투영을 사용하고, 시작 머리는 채운 막대·끝은 테두리 막대·몸통은 중심선으로 구분합니다. 누르는 동안 머리가 판정선에 머물고 몸통과 버튼 테두리가 밝아집니다. 동작 줄이기에서도 모양을 유지합니다.

## 판정과 점수

- 시작은 탭과 같은 PERFECT ±45ms / GREAT ±90ms / GOOD ±140ms입니다. `keydown` 또는 `pointerdown`으로만 시작하며, 너무 일찍 눌러 고정하거나 OS repeat로 시작할 수 없습니다.
- 시작 때는 HOLD 피드백과 타격음만 발생하고 점수·콤보는 대기합니다. 끝 시각까지 누르면 시작 판정으로 정확히 한 번 성공합니다. 끝의 80ms 전부터 놓아도 같은 성공 판정을 허용합니다. 80ms보다 일찍 놓거나 시작을 놓치면 MISS 한 번이며 콤보가 끊깁니다.
- 실패한 홀드를 다시 눌러도 구제되거나 두 번 점수가 생기지 않습니다. 완료 후 늦게 놓아도 추가 점수는 없습니다. 유지 입력 자체는 EMPTY가 아니며, 다른 빈 레인의 새 입력은 기존 EMPTY 규칙을 따릅니다.
- 홀드 전체가 노트 하나입니다. 총노트 243, 최고점 1,000,000, 정확도·등급·콤보·보상 공식은 동일합니다. 시작/끝을 따로 노트 수나 MISS 수에 더하지 않습니다. 타격음은 시작에 한 번, 콤보 보상은 성공 완료 때 적용합니다.
- 같은 레인의 키보드/포인터 중 하나라도 실제로 누르고 있으면 유지합니다. 마지막 입력의 `keyup`/`pointerup`/`pointercancel`에서 해제합니다. 포인터는 버튼 바깥에서 놓아도 처리합니다. 접근성 버튼의 단발 클릭은 유지가 아니므로 홀드는 실패합니다. 키보드 레인 키를 길게 누르거나 포인터를 유지해야 합니다.
- 시간은 기존 오디오 출력 시계와 싱크 보정을 사용합니다. 끝 성공과 지나간 노트 MISS는 음악 시각 순서로 처리합니다. 곡 종료 시 남은 홀드는 성공 또는 MISS로 반드시 한 번 정산합니다.

새 채보의 최고 기록 키는 `astral-veil:6k:normal:hold-v1`입니다. 이전 탭 전용 LEVEL 2·6키 기록은 로컬 저장소에 보존하되 새 홀드 채보의 최고 기록과 비교하지 않습니다. 다른 모드의 기록 키와 기존 4키 기록 읽기는 유지합니다. 공개 발표 영상은 이전 탭 채보 시연이며 재생성하지 않습니다.

## 일시정지와 포커스 복귀

일시정지·창 포커스 상실·탭 전환 때 음악이 멈추고 입력 소유권을 비웁니다. 진행 중 홀드는 실패 없이 대기합니다. 재개할 때는 멈춘 홀드의 키를 **새로 눌러 유지한 뒤 Enter/계속 플레이**를 누릅니다. 포인터는 일시정지 대화상자의 해당 키 버튼을 누른 채 재개할 수 있습니다. 키보드로 이 버튼에 포커스를 옮겨 Space를 유지해도 복구할 수 있으며, 대화상자가 닫힌 뒤의 Space 해제도 처리합니다. 필요한 키가 눌리지 않았으면 음악을 계속 멈추고 안내를 표시합니다. 음악이 기다리므로 짧은 복귀 제한 시간 때문에 실패하지 않습니다.

대기 중 키를 놓거나 다시 포커스를 잃으면 해당 키는 다시 누르도록 표시합니다. 일반 레인의 일시정지 입력은 판정하지 않습니다. 모든 필요한 키를 누른 상태에서 음악 재개가 완료된 이후의 실제 해제는 정상 홀드 판정을 따릅니다. 재개 비동기 처리 중 해제되면 음악을 다시 멈추고 재입력을 기다립니다. 오디오 일시정지 자체가 실패한 예외 경로에서는 입력 상태를 잃은 홀드를 MISS로 정산하고 오류 안내를 표시합니다. 재시도·메뉴 복귀는 이전 홀드 상태를 이어받지 않습니다.

## 재현 검사

```sh
npm test
npm run check
QA_INPUT_DRIVER=page npm run verify:demo
npm run verify:holds
npm run verify:input
```

`verify:holds`는 임시 Chrome 프로필에서 실제 CDP 키/마우스 누름·해제를 수행합니다. 시작/키 유지/repeat, 80ms 안쪽 해제, 중도 해제·재누르기, 너무 이른 고정 키, 놓친 시작, 끝 전후 해제, 실제 탭 전환, 키 복구 전 재개 차단, 포인터 복구 후 대화상자 캡처 상실과 버튼 밖 해제, 재시도를 확인합니다. 첫 완주는 일부 홀드를 의도적으로 실패하며, 두 번째 완주는 모든 시작/끝 입력을 현재 시각의 KeyboardEvent로 예약해 243 PERFECT·100만점·100%·FULL COMBO를 확인합니다. 375px·844px 가로·동작 줄이기 PNG도 저장합니다. 약 3분이며 `QA_HOLD_SHORT=1`은 첫 두 홀드와 재시도만 확인합니다.

`QA_URL=https://perspicacia.github.io/pulse-shift-demo/ QA_HOLD_SHORT=1 npm run verify:holds`로 공개 배포의 핵심 검사를 수행할 수 있습니다. `QA_PORT`(기본 4198)·`CHROME_PATH`를 지정할 수 있습니다. 결과·입력 로그·화면은 Git 제외된 `artifacts/hold-qa/`에 저장합니다.

단위 검사는 정확한 시작/80ms 끝 경계, 두 동시 홀드와 다른 레인 탭, 시간순 MISS, 중복 점수·보상 방지, 일시정지 상태와 재시도, 음악 그리드/레인 충돌과 12개 지원 조합의 정상·난타를 검사합니다. `verify:input`의 200ms 전 키 누름/즉시 해제에서는 8개 홀드가 MISS가 되어야 하며, 다른 대표 모드의 MISS 0 조건은 유지합니다. 기존 전체 곡 자동 검사도 끝까지 실제 입력을 유지한 후 해제합니다. 판정·채보·시계·점수를 조작하지 않습니다.

이 자동 검사는 물리 키보드 지연, 실제 모바일 터치, 청감·블루투스/디스플레이 지연이나 재미를 보장하지 않습니다. 실제 장치에서는 몸통의 읽기 쉬움과 키 유지 느낌을 별도로 확인합니다.
